1 The Coordinate Systems

We establish a reference origin on the ceiling ($y = 0$). The position coordinate axes point downward:

$y_1(t)$ : Block 1 position $y_b(t)$ : Pulley B position $y_2(t)$ : Block 2 position

Because the coordinate functions increase downwards, their second derivatives are the downwards accelerations: $$a_1 = \frac{d^2y_1}{dt^2}, \quad a_2 = \frac{d^2y_2}{dt^2}, \quad a_b = \frac{d^2y_b}{dt^2}$$

2 String 2 Constraint

Block 2 is linked directly to Pulley B via a fixed-length string $l_2$: $$\text{Length } l_2 = y_2 - y_b = s_2 \quad \text{(constant)}$$ Taking two time derivatives yields: $$\frac{d^2l_2}{dt^2} = a_2 - a_b = 0 \implies \mathbf{a_2 = a_b}$$ Thus, Pulley B and Block 2 must move in lockstep acceleration.

3 String 1 Geometric Constraint

The primary string wraps from the ceiling anchor, around the bottom of Pulley B, over Fixed Pulley A, down to Block 1. Its total length $l_1$ is modeled as: $$\text{Length } l_1 = y_b + \pi R + (y_b - s_1) + \pi R + (y_1 - s_1)$$ Collecting constants and simplifying: $$l_1 = 2y_b + y_1 + C \quad \text{where } C = 2\pi R - 2s_1$$

4 The Core Constraint Relation

Differentiating $l_1$ twice with respect to time ($dl_1/dt = 0$): $$2\frac{d^2y_b}{dt^2} + \frac{d^2y_1}{dt^2} = 0 \implies 2a_b + a_1 = 0$$ Substituting $a_b = a_2$ from step 2, we arrive at our crucial constraint: $$\mathbf{a_1 = -2a_2} \quad \text{or} \quad \mathbf{2a_2 + a_1 = 0}$$ This means if Block 2 accelerates downwards by $1\text{ m/s}^2$, Block 1 must accelerate upwards by $2\text{ m/s}^2$.

5 Solving Newton's Equations

Let $T$ be the tension of String 1. Under ideal, massless pulleys, the tension on String 2 must balance $2T$. We apply Newton's 2nd Law (downwards positive): $$1) \quad m_1 g - T = m_1 a_1$$ $$2) \quad m_2 g - 2T = m_2 a_2$$ Substituting $a_2 = -\frac{a_1}{2}$ and solving the simultaneous equations yields: $$\mathbf{a_1 = \frac{2g(2m_1 - m_2)}{4m_1 + m_2}} \quad \text{and} \quad \mathbf{T = m_1(g - a_1)}$$

To build the dynamic simulator, we run an Euler-Cromer integration loop at 60 FPS. Here is the exact mathematical algorithm written in clean, optimized JavaScript: 

// 1. Retrieve Current Physical Parameters
const m1 = params.m1;
const m2 = params.m2;
const g = params.g;

// 2. Solve Analytical Equations (Calculated at each tick)
const numerator = 2 * g * (2 * m1 - m2);
const denominator = (4 * m1) + m2;
const a1 = numerator / denominator;  // Block 1 acceleration
const a2 = -a1 / 2;                  // Block 2 acceleration (via constraint)
const ab = a2;                       // Pulley B acceleration

// 3. Solve Tension Forces
const T1 = m1 * (g - a1);            // Tension in String 1
const T2 = 2 * T1;                   // Tension in String 2

// 4. Euler-Cromer Numerical Integration
v1 += a1 * dt;                       // Update velocities
v2 += a2 * dt;

y1 += v1 * dt;                       // Update position coordinates
y2 += v2 * dt;
yb = y2 - s2;                        // Pulley B dynamic position

// 5. Collision & Boundary Checks
if (y1 >= floorLimit || y1 <= ceilingLimit) {
    v1 = 0; v2 = 0; // Halt system safely
}
Why use Euler-Cromer over standard Euler?

In traditional Euler integration, position is updated using the *old* velocity ($y(t+dt) = y(t) + v(t)dt$). Euler-Cromer updates the velocity first, then uses the *newly computed* velocity to update the position. This preserves energy conservation properties for harmonic and bounded mechanical systems.
