Mathematical Derivation Blueprint

1

Observer's Two-Stage Calculus ($x_1$)

Initially you are at rest, accelerating at constant rate $b_1$ until $t_1$. Integrating your acceleration:

$$\text{For } 0 \le t \le t_1:$$ $$v_1(t) = \int_0^t b_1 \, dt' = b_1 t$$ $$x_1(t) = \int_0^t (b_1 t') \, dt' = \frac{1}{2} b_1 t^2$$

At $t_1$, you switch to constant coasting. For any time $t > t_1$, you continue with speed $v_1(t_1) = b_1 t_1$:

$$\text{For } t > t_1:$$ $$v_1(t) = b_1 t_1$$ $$x_1(t) = x_1(t_1) + \int_{t_1}^t v_1(t') \, dt' = \frac{1}{2} b_1 t_1^2 + b_1 t_1 (t - t_1)$$ $$x_1(t) = b_1 t_1 t - \frac{1}{2} b_1 t_1^2$$
2

Bicyclist's Uniform Deceleration ($x_2$)

The bicyclist enters with speed $v_{2,0}$ and slows down at $b_2$. Their equations of motion are straightforward:

$$v_2(t) = v_{2,0} - b_2 t$$ $$x_2(t) = v_{2,0} t - \frac{1}{2} b_2 t^2$$
3

Linking the Meeting Boundary Conditions

At the meeting point ($t = t_2$), two exact matching conditions must occur:

  1. The cyclist must reach a complete halt: $v_2(t_2) = 0 \implies t_2 = \frac{v_{2,0}}{b_2}$.
  2. Both of you must share the same physical coordinates: $x_1(t_2) = x_2(t_2)$.

Substituting $t_2$ into $x_2$ yields:

$$x_2(t_2) = v_{2,0} \left(\frac{v_{2,0}}{b_2}\right) - \frac{1}{2} b_2 \left(\frac{v_{2,0}}{b_2}\right)^2 = \frac{v_{2,0}^2}{2 b_2}$$
4

The Algebraic Solver

Now, set $x_1(t_2) = x_2(t_2)$:

$$b_1 t_1 \left(\frac{v_{2,0}}{b_2}\right) - \frac{1}{2} b_1 t_1^2 = \frac{v_{2,0}^2}{2 b_2}$$

Multiply both sides by $2 b_2$ and isolate $b_2$:

$$2 b_1 t_1 v_{2,0} - b_1 t_1^2 b_2 = v_{2,0}^2$$ $$b_1 t_1^2 b_2 = 2 b_1 t_1 v_{2,0} - v_{2,0}^2$$ $$b_2 = \frac{2 b_1 t_1 v_{2,0} - v_{2,0}^2}{b_1 t_1^2}$$
Board Discrepancy Note: On the blackboard, the equation was initially written with a slight factor error in writing the shorthand but was evaluated perfectly to $\frac{3}{2}\text{ m/s}^2$ ($1.5$). The algebra shown here is 100% rigorous and exact!

Computation & Simulation Logic

How does our simulator evaluate the exact physical trajectory of both objects frame-by-frame? Let's take a look under the hood.

Step-by-Step Simulation Evaluation Loop 
// 1. Gather configured initial parameters
const b1 = parseFloat(document.getElementById('slider-b1').value);
const t1 = parseFloat(document.getElementById('slider-t1').value);
const v20 = parseFloat(document.getElementById('slider-v20').value);

// 2. Solve analytically for required deceleration
const b2 = (2 * b1 * t1 * v20 - Math.pow(v20, 2)) / (b1 * Math.pow(t1, 2));

// 3. Compute terminal meeting duration
const t2 = v20 / b2;

// 4. Update the simulation state inside window loop
function updatePositions(t) {
  // You (Object 1): Piecewise Kinematic Logic
  let x1, v1;
  if (t <= t1) {
    v1 = b1 * t;
    x1 = 0.5 * b1 * Math.pow(t, 2);
  } else {
    v1 = b1 * t1;
    x1 = 0.5 * b1 * Math.pow(t1, 2) + (b1 * t1) * (t - t1);
  }

  // Cyclist (Object 2): Decelerating logic
  let v2 = Math.max(0, v20 - b2 * t);
  let x2 = v20 * t - 0.5 * b2 * Math.pow(t, 2);
  if (t > t2) {
    x2 = v20 * t2 - 0.5 * b2 * Math.pow(t2, 2); // Stop moving after rest
  }

  return { x1, v1, x2, v2 };
}
Algorithm Checklist for Physics Validity
  • Zero overshoot: The cyclist stops exactly when $v_2 = 0$ ($t = t_2$) and remains stationary.
  • Piecewise smooth boundary: Velocity of $x_1$ must be continuous at $t_1$.
  • Real-time scaling: Animation canvas dynamically computes optimal pixel ratios based on the calculated maximum distance.
